Editor notes

What runs here, and what needs a build step

This editor previews files the way a browser reads them: HTML, CSS and JavaScript loaded directly, no bundler in between. That constraint is what makes the preview instant, and it is also the reason some code that works in a React project will fail here without explanation.

Runs as-is

  • Plain <script> and <style> blocks, inline or linked as separate files.
  • ES modules via <script type="module">, as long as the import paths are relative and the files exist in the same project.
  • Any library loaded from a CDN, for example a charting library or a date formatter.

Does not run

  • import statements for packages that were never installed — there is no node_modules, so a bare specifier like import x from 'lodash' resolves to nothing.
  • JSX and TypeScript without a compile step. Browsers do not parse either.
  • Server-side code. PHP, Python, and Node handlers have no runtime here; anything that needs a server has to be hosted elsewhere and called over HTTP.
  • fetch() against a third-party API that does not send CORS headers. The request leaves the browser and the response is blocked on return — the failure appears in the console, not in the page.

What the exported ZIP contains

The export is the project as files, not a snapshot: index.html, any CSS and JavaScript you created, and an assets folder if images were added. Unzip it into an empty directory and open index.html directly — it should behave the same as the preview. If it does not, the usual cause is an absolute path written as /style.css, which resolves to the filesystem root once the file is opened from disk instead of served. Relative paths avoid this entirely.

Checking mobile width before you export

The 390px preview is a real layout width, not a scaled screenshot. Two things it catches reliably: text that overflows a flex container because a child has no min-width: 0, and tap targets that fall under roughly 44px once padding collapses. Two things it cannot catch: keyboard behaviour when the on-screen keyboard covers half the viewport, and font rendering differences on iOS. Both need a real phone.

Nothing is uploaded during editing. The project lives in this browser session. Export is the only way out, and it is also the backup — if the tab is closed before exporting, the work does not survive.
