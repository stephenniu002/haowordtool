Learning path

Three lessons, one page you can actually open

The lessons are ordered so that each one ends with something you can check, not something you have read. By the third lesson you have a folder that opens in a browser from disk, with no editor and no server involved.

What you need before lesson 1

A browser and a text editor. That is the whole list — no Node, no package manager, no account. Lesson 1 starts from a working example page rather than an empty file, because the fastest way to learn what code does is to change one line of code that already works and watch what breaks.

What each lesson leaves behind

Lesson 1 — running AI-generated HTML, CSS and JavaScript
You end up with a page that loads and responds to a click. The check is behavioural: press the button, watch the counter change. If it changes, the script parsed and attached its listener; if nothing happens, the console names the line.
Lesson 2 — previewing at mobile width
You end up with a layout that survives 390px. The check is visual and specific: no horizontal scrollbar, form fields reachable with one thumb, long labels wrapping instead of being clipped. A layout that only looks right at desktop width is not finished, it is unstarted.
Lesson 3 — exporting as a working ZIP
You end up with files that work outside the editor. The check is the one most people skip: unzip into a new folder, open index.html from disk, and confirm it still looks correct. Paths that were absolute silently break at exactly this moment.

The three mistakes that account for most failures

  1. Absolute paths. src="/app.js" works while served from a root, and points at the drive root once the file is opened from disk. Use src="./app.js".
  2. Script placed before the element it targets. getElementById returns null and the next line throws. Either move the script to the end of the body or attach it with defer.
  3. Assuming the preview equals a phone. Width is reproducible; the on-screen keyboard, iOS font rendering and touch scroll behaviour are not. Anything involving typing needs a real device check.

Keep the example, not just your version. When a change breaks the page, the fastest recovery is a diff against the original. Save a copy of the example before you start editing — it costs one keystroke and saves an evening.
