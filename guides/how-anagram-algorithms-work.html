How an Anagram Algorithm Works

A plain-language explanation of letter signatures, multisets, wildcards, filtering, and ranking.

By HaoWord Studio Editorial · 10 min · Updated 2026-08-28

Represent letters as counts

A reliable solver treats letters as a multiset: AELRST becomes {a:1,e:1,l:1,r:1,s:1,t:1}. A candidate is valid when none of its letter counts exceed the rack counts. This prevents a candidate such as TREAT from using two T tiles when only one exists.

Exact and subset searches differ

For an exact anagram, candidate length equals rack length and every count must match. For an unscramble search, candidates may use a subset. The distinction changes both correctness and performance, so the interface should state which mode is active.

Handle wildcards explicitly

A wildcard covers each missing count up to the number of blanks. It should not be converted into a chosen letter before candidate testing. After matching, the interface can highlight which letters consumed blanks so players understand the result.

Rank for human usefulness

Alphabetical output is correct but not always helpful. Ranking by length, then game score, then familiarity puts likely choices first. A transparent rank is preferable to unexplained “AI” ordering; users should know why a word appears above another.

Sorting letters into a signature

The multiset test described above is easy to state but slow if you run it naively against every word in a dictionary of 170,000 entries for every keystroke. Production solvers therefore precompute. The classic trick is the alphabetical signature: sort each dictionary word's letters once, offline, so that LISTEN, SILENT and ENLIST all collapse to the same key, EILNST. Exact-anagram lookup then becomes a single dictionary access — sort the rack, read off the bucket. Signature indexing turns an expensive scan into a near-instant lookup, and it is why exact anagram tools feel immediate even on a phone.

Subset search — finding every word that fits inside a rack, the mode word games actually need — cannot use a single bucket, because a seven-letter rack has dozens of sub-multisets. Solvers handle it in two ways. The first generates every sub-multiset of the rack and checks each against the signature index; with blanks removed, a seven-letter rack has at most 128 sub-multisets, which is cheap. The second walks a trie of the dictionary, consuming letters from the rack as it descends and pruning any branch whose next letter the rack cannot supply. Trie walking visits far fewer nodes than a full scan and naturally produces words grouped by prefix, which is convenient for players hunting a specific opening.

Wildcards, blanks and fixed letters

A blank tile breaks the counting logic unless the solver treats it as a budget rather than a letter. The standard approach runs the search once per possible substitution only in the worst case; smarter implementations add a deficit rule: a candidate word is playable if the number of letters it needs beyond the rack is no greater than the number of blanks held. During a trie walk, the solver tracks how many blanks have been spent on the current path and abandons branches that overspend. Fixed letters — tiles already on the board that a play must pass through — are handled by splitting the rack: letters before and after the fixed letter are searched as constrained patterns, which is why board-aware solvers ask where the fixed letter sits, not just what it is.

Why ranking matters as much as matching

A seven-letter rack with two blanks can match thousands of words. Returning them alphabetically buries the plays a human would actually choose, so solvers rank. Sensible ranking signals include word length (longer plays usually score more and always clear rack space), game score computed from letter values, and the leave — the tiles remaining after the play, where keeping a balanced vowel-consonant mix and avoiding duplicate letters genuinely improves the next rack. Frequency in real text is a weaker but useful signal for learners, who want common words first. This site's solver ranks by usefulness for study and play rather than by raw score alone, and the ordering rule is documented instead of hidden, because a ranking you cannot inspect is a ranking you cannot learn from.

Where solvers disagree

Two correct solvers can return different lists from the same rack, and the difference is almost never the algorithm — it is the dictionary. Tournament Scrabble in North America uses one official word list, international play uses another, and family games often use a general dictionary that admits words both tournament lists reject, such as some proper-derived terms, while excluding obscure valid plays. Definitions differ too: a solver built for vocabulary study may filter out words it cannot define. When a word you expect is missing, check which list the tool loads before blaming the search. Quick review

The strongest habit is to separate hard constraints—letter counts, length, fixed positions—from helpful clues such as frequency and familiar patterns. Use the tool to narrow possibilities, then use meaning and context to choose.
